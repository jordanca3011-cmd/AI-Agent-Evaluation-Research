# Working Within Real-World Limits

Another part of this project came from a practical problem: cost.

As I explored increasingly capable AI systems, I started looking at APIs and ways of connecting models directly to development tools.

I quickly realised that building everything around paid API usage could become expensive, especially for the kind of long-running experimentation I wanted to do.

Game development can involve hundreds or thousands of interactions across planning, coding, debugging, Blender work, testing and iteration. An AI system that is affordable for a short demonstration may become much more expensive when used continuously throughout an entire development project.

As an independent developer, I did not have an unlimited research budget.

That led to another question:

> **How much can I achieve using the AI access, subscriptions, local hardware and development tools I already have?**

Instead of assuming that the solution was always to spend more money on API calls, I started experimenting with different approaches.

---

## Trying to Avoid Unnecessary API Costs

I explored ways of using AI systems without making paid API usage the foundation of the entire workflow.

This included experimenting with combinations of:

- Chat-based AI systems
- Subscription-based AI tools
- Local AI models
- Coding agents
- Local development tools
- Blender automation
- Roblox development tools
- Computer-use systems
- Structured project documentation
- Persistent project context
- Human-controlled handovers between tools

This changed how I thought about AI-assisted development.

Initially, I imagined that the best system would probably be a completely automated collection of models connected together through APIs.

Over time, I discovered that this was not necessarily the most practical approach for me.

Sometimes a better result could come from improving the workflow rather than adding another model.

---

# Making the Most of the Tools I Already Have

A major part of my experimentation became learning how to make better use of the capabilities already available to me.

Instead of constantly asking:

> "What new AI do I need?"

I started asking:

> "How can I use what I already have more effectively?"

That led to improvements in areas such as:

- Breaking large objectives into controlled stages
- Keeping structured project documentation
- Recording important decisions
- Giving AI systems better project context
- Separating planning from implementation
- Using specialised tools for specialised tasks
- Verifying project state before continuing
- Creating handovers between sessions
- Testing changes before moving to the next stage
- Preserving successful workflows so they can be reused

I found that the way an AI system is used can be just as important as which model is being used.

A powerful model given poor context and an unclear workflow can still produce poor results.

A more structured workflow can sometimes allow the same available tools to perform much better.

---

# Developing Better AI Working Routines

This led me to start developing repeatable working routines for AI-assisted development.

A typical workflow increasingly became closer to:

```text
Define Goal
     ↓

     ↓

     ↓
Record What Changed
     ↓
Update Project Context
     ↓
